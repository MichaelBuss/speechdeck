# A Release PR is the only publish lever; every version ships to npm and JSR

Releases run through Changesets instead of the hand-rolled bump/comment machinery. Version intent lives inside each PR as a `.changeset/*.md` file — a bump kind plus a note that becomes the changelog entry — rather than version edits on a PR branch: two concurrent PRs both editing five `package.json` / `jsr.json` pairs conflict at merge time, and the loser's bump is computed against a stale base, which is exactly what small uniquely-named files avoid. `changesets/action` accumulates pending changesets into one **Version Packages PR** that bumps `package.json` and writes `CHANGELOG.md` (`@changesets/changelog-github` renders notes with PR and author links); `scripts/sync-versions.ts` then drags every `jsr.json` to its `package.json` version, because each package's manifest pair is an invariant, not a convention, and the pnpm lockfile needs no sync since workspace deps use `workspace:*`. The `fixed: [["@speechdeck/*"]]` group carries over the lockstep the old `bump.ts` enforced: all five packages move as one version, one `vX.Y.Z` tag, one GitHub Release. Merging that PR is the only way a release happens: the same workflow then runs `scripts/release.ts`, which per package publishes npm via trusted publishing (OIDC through `id-token: write`, `--provenance`, no long-lived token) and JSR via OIDC, then tags and creates the GitHub Release from generated notes; every step checks what the registries already have, so a re-run after a partial failure and an ordinary docs-only merge to `main` both publish nothing and stay green, and one registry or package failing does not block the rest. Neither registry understands `workspace:*`, so the release script pins sibling deps per registry for the publish — npm takes `^x.y.z`, JSR takes its `npm:@jsr/speechdeck__*` compat specifier — and restores `package.json` after; packages also gained `repository` (npm provenance requires it to match) and `files` (so the npm tarball mirrors the jsr.json publish config) fields. This supersedes ADR 0021: the `/bump` comment, `bump.ts`, `should-publish.ts`, `publish-jsr.mjs`, and the version-based publish-preview comment are deleted; the informational spirit survives as the release-guidance PR comment, which reads the PR's changesets per package and nudges on missing `Closes #N` but never gates. npm publishing not being configured yet is a human step that fails instructively, with claim-scope / trusted-publishing / re-run instructions on the workflow summary and the merged PR, never a silent skip. Until that setup lands, the npm half of a release fails and the JSR half still ships.

Human-only steps and the agent rules live in `docs/agents/release.md`, linked from `AGENTS.md`.
