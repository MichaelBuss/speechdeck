# Code pairing is positional, minted once per transition — not per Frame

ADR 0019 scoped code-Cell pairing out: `matchCode` threw "not implemented" and `resolveFrame`'s `names` only walked headings and images. This closes that gap.

A heading or image mints its `Named` independently per Frame because its identity comes from content that is expected to *persist* (the same text, the same src) across the edge. Code has no such identity — the whole point of a code morph is that the bytes changed, so a content hash would never agree between the outgoing and incoming Cell. The glossary already settled the shape: code Cells pair by index. `matchCode(from, to)` in `@speechdeck/core` takes the pair already aligned by position and returns a `CodeMatch`: `pairing: "morph"` when the pair should morph, `"none"` when it should not (a language swap is not the same Cell persisting, so it does not pair even at a shared index), and a `key` minted from both sides together — unlike a heading's name, this key only has to agree between this transition's two elements, not across the Deck, so it is computed once and reused, not independently re-derived on each side.

The Solid adapter — the only caller — does the positional zip: `pairCodeCells` walks `from.slide`'s and `to.slide`'s code Cells in document order, pairs index-for-index up to the shorter side's length, and calls `matchCode` once per shared index. A leftover Cell past that length is never paired, never named, and so never morphs — no special-case leftover handling, the absence of a call is the whole mechanism. The resulting keys are stamped via `applyCodePairings`, mirroring `applyNames`'s outgoing-then-incoming shape inside the same `document.startViewTransition` call already wired in ADR 0019. A hard cut never reaches that call, so code on a hard cut is never named, matching headings and images.

Core exposes `matchCode` only; it does not touch `Frame.names`, `resolveFrame`'s signature, or highlighting. Shiki still runs solely in `@speechdeck/vite` (ADR 0003); this ticket also filled in the Solid adapter's missing `code` Cell render branch (`data-kind="code"`, Shiki's `html` painted verbatim) since a code Cell could not morph, or appear at all, without it.
